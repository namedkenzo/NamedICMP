# namedICMP

جدید در نسخه 0.3.0: [کلاینت اختصاصی namedP برای ویندوز](docs/NAMEDP.md) با VPN کل سیستم روی IPv4 و پروکسی SOCKS5. وضعیت آزمون و محدودیت‌ها در [یادداشت انتشار](docs/RELEASE-v0.3.0.md) آمده است.

نسخه و ریلیز این دو مستقل‌اند: پنل و سرور **namedICMP 0.3.0** با تگ
`v0.3.0` و کلاینت ویندوز **namedP 0.1.0-alpha** با تگ
`namedp-v0.1.0-alpha`. فایل ZIP ویندوز از ریلیز namedP دانلود می‌شود؛
نصب‌کننده لینوکس فقط پنل و سرور را نصب می‌کند.

**پنل مدیریت و هستهٔ مستقل Go برای انتقال TCP و UDP روی ICMP نسخهٔ ۴.**

[English](README.md) · [دانلود ریلیزها](https://github.com/namedkenzo/NamedICMP/releases) · [راهنمای ویندوز](docs/WINDOWS.md)

با یک پنل فارسی/انگلیسی، کاربر بسازید، حجم و تاریخ انقضا تعیین کنید و برای هر کاربر خروجی مستقیم یا پروکسی انتخاب کنید. پنل و هسته در یک سرویس لینوکسی اجرا می‌شوند و برای اجرا به Node.js، سرور دیتابیس یا سرور جداگانهٔ PingTunnel نیاز ندارند.

## امکانات

- انتقال مستقل TCP و UDP روی ICMP و محاسبهٔ مصرف هر کاربر.
- فعال/غیرفعال‌کردن کاربر، تعیین حجم و تاریخ انقضا و کپی لینک اتصال.
- فقط **یک روش دسترسی برای هر کاربر**: رمز عددی **یا** رمزنگاری AES-128-GCM، AES-256-GCM یا ChaCha20-Poly1305 با کلید تولیدشده.
- خروجی مستقیم، SOCKS5 برای TCP/UDP و HTTP CONNECT برای TCP.
- پنل فارسی/انگلیسی، حالت روشن/تیره، نمایش منابع و وضعیت تونل‌ها.
- مدیریت با systemd، گواهی HTTPS اختیاری با Certbot، بکاپ هنگام آپدیت و بازگردانی باینری در صورت شکست بررسی سلامت.

هسته به‌صورت مستقل پیاده‌سازی شده و قالب پیام‌های شبکه با PingTunnel سازگار است؛ باینری PingTunnel داخل سرور توزیع نمی‌شود. سازگاری نهایی به نسخه و قابلیت‌های کلاینت هم بستگی دارد.

## نصب

پیش‌نیاز: **Debian/Ubuntu با systemd**، دسترسی root، ارتباط IPv4 عمومی و معماری **amd64 یا arm64**. در فایروال سرور و ارائه‌دهنده، ICMP نسخهٔ ۴ و پورت TCP انتخابی پنل را مجاز کنید.

در ترمینال تعاملی با دسترسی root اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/namedkenzo/NamedICMP/main/install.sh -o /tmp/namedicmp-install.sh
bash /tmp/namedicmp-install.sh
```

گزینهٔ **۱ — Install** را انتخاب کنید؛ سپس پورت پنل، آدرس عمومی سرور و اطلاعات مدیر را وارد کنید. آدرس مخزن از قبل `namedkenzo/NamedICMP` است و دیگر پرسیده نمی‌شود.

نصب اینترنتی ابتدا باینری آمادهٔ همان نسخه را دریافت می‌کند و checksum نوع SHA-256 و نسخهٔ فایل اجرایی را بررسی می‌کند؛ بنابراین دانلود Go و کامپایل روی سرور لازم نیست. اگر دانلود ریلیز در دسترس نباشد، حالت خودکار با نمایش توضیح از سورس می‌سازد. checksum نامعتبر نصب را متوقف می‌کند. زمان نصب به شبکه و APT وابسته است و زمان ثابت تضمین نمی‌شود.

فقط وابستگی‌های نصب‌نشده دریافت می‌شوند. برای جلوگیری از پاسخ‌های تکراری تونل، پاسخ معمول ping کرنل غیرفعال می‌شود؛ حذف برنامه در شرایط مناسب مقدار قبلی را برمی‌گرداند. آدرس HTTP/HTTPS پس از نصب نمایش داده می‌شود. برای HTTPS باید دامنه به سرور اشاره کند و پورت TCP شمارهٔ ۸۰ برای Certbot آزاد و قابل‌دسترسی باشد. در صورت انتخاب دسترسی محلی HTTP، از دستور SSH tunnel نمایش‌داده‌شده استفاده کنید.

برای بازکردن دوبارهٔ منو:

```bash
namedicmp
```

## آپدیت

**نصب‌کنندهٔ جدید را با همان دستور بالا اجرا کنید** و گزینهٔ **۲ — Update** را بزنید؛ این روش برای ارتقا از منوی قدیمی هم مناسب است. کاربران، مصرف، حجم، اطلاعات مدیر و تنظیمات TLS حفظ می‌شوند. تونل‌ها هنگام تعویض نسخه یک‌بار دوباره متصل می‌شوند. اگر بررسی سلامت ناموفق باشد، باینری قبلی بازگردانده می‌شود. مسیر بکاپ‌ها: `/var/lib/namedicmp/backups`.

**ارتقای کاربران رمزنگاری‌شده از 0.2.1:** کانفیگ این کاربران را دوباره کپی و در کلاینت وارد کنید. در روش رمزنگاری دیگر رمز عددی استفاده نمی‌شود؛ دستورهای قدیمی که هم `-key` و هم encryption دارند باید جایگزین شوند. کانفیگ کاربران صرفاً عددی معتبر می‌ماند.

## اتصال کلاینت

در بخش **کاربران** کاربر بسازید و روش دسترسی را انتخاب کنید. سپس **کانفیگ** را باز کنید و لینک یا دستور اتصال را کپی کنید.

| روش کاربر | تنظیمات کلاینت |
| --- | --- |
| رمز عددی، بدون رمزنگاری (`none`) | آدرس سرور و رمز عددی؛ encryption خاموش |
| رمزنگاری | آدرس سرور، الگوریتم و کلید Base64؛ بدون رمز عددی |

تغییر روش، روش دسترسی فعال را جایگزین می‌کند و اتصال‌های همان کاربر را قطع می‌کند. کاربران رمزنگاری‌شده در فایل سرور یک شناسهٔ داخلی برای مسیریابی دارند؛ این شناسه رمز کلاینت نیست و در کانفیگ صادر نمی‌شود. رمز عددی به‌تنهایی ترافیک را رمزنگاری نمی‌کند. HTTPS پنل و رمزنگاری تونل تنظیمات جداگانه‌اند.

- **کلاینت خط فرمان دسکتاپ:** [ریلیزهای اصلی PingTunnel](https://github.com/esrrhs/pingtunnel/releases). نسخهٔ ویندوز موجود است و باید با دسترسی Administrator اجرا شود. برای رمزنگاری، نسخه‌ای لازم است که `-encrypt` و `-encrypt-key` را پشتیبانی کند.
- **اندروید و رابط گرافیکی دسکتاپ:** [PingTunnel Client جامعهٔ کاربران](https://github.com/itismoej/pingtunnel-client/releases). این کلاینت در حالت رمزنگاری، کلید رمزنگاری را به‌جای رمز عددی استفاده می‌کند.
- **iOS:** [Ping Tunnel](https://apps.apple.com/us/app/ping-tunnel-vpn-over-icmp/id6748279683). پیش از انتخاب رمزنگاری، پشتیبانی نسخهٔ نصب‌شده از روش دسترسی را بررسی کنید.

برای عیب‌یابی ویندوز و بررسی امکان ساخت کلاینت اختصاصی، [راهنمای ویندوز](docs/WINDOWS.md) را بخوانید. حالت SOCKS فقط برنامه‌هایی را عبور می‌دهد که برای استفاده از پروکسی تنظیم شده‌اند. UDP به پشتیبانی کلاینت، برنامهٔ مصرف‌کننده و خروجی وابسته است؛ خروجی HTTP CONNECT فقط TCP را عبور می‌دهد.

## رفع مشکلات رایج

| مشکل | بررسی |
| --- | --- |
| نصب وارد کامپایل طولانی می‌شود | فایل‌های ریلیز همان نسخه موجود یا قابل‌دسترسی نیستند. هر دو آرشیو لینوکس و `SHA256SUMS` باید منتشر شوند. |
| دانلود یا checksum خطا دارد | دسترسی به فایل‌های GitHub را بررسی و دوباره تلاش کنید؛ بررسی checksum را حذف نکنید. |
| پنل باز نمی‌شود | گزینه‌های Status و Recent logs، اشغال‌بودن پورت، آدرس bind و فایروال را بررسی کنید. |
| Certbot خطا می‌دهد | DNS عمومی، دسترسی ورودی TCP 80 و اشغال‌نبودن آن را بررسی کنید؛ سپس SSL certificate را دوباره اجرا کنید. |
| کلاینت متصل نمی‌شود | یکسان‌بودن روش دسترسی، مجوز Administrator یا raw socket و عبور ICMP نسخهٔ ۴ از فایروال را بررسی کنید. |
| TCP کار می‌کند ولی UDP نه | پشتیبانی UDP کلاینت و SOCKS5 UDP ASSOCIATE را بررسی کنید؛ خروجی HTTP فقط TCP دارد. |

تنظیمات در `/etc/namedicmp/config.json` و اطلاعات کاربران در `/var/lib/namedicmp/state.json` هستند. دو نمونهٔ سرور را هم‌زمان روی یک فایل وضعیت اجرا نکنید.

```bash
systemctl status namedicmp --no-pager
journalctl -u namedicmp -n 60 --no-pager
/opt/namedicmp/namedicmp diagnostics
```

## ساخت و انتشار

ساخت از سورس به Go نسخهٔ **1.26 یا جدیدتر** نیاز دارد. Node.js فقط برای تست اختیاری رابط در زمان توسعه استفاده می‌شود.

```bash
go test -race ./...
go vet ./...
bash scripts/test_installer.sh
bash scripts/test_update.sh
bash scripts/build.sh
```

خروجی در `dist/` ساخته می‌شود. نصب از checkout محلی، همان سورس محلی را کامپایل می‌کند. برای اجبار روش نصب، `NAMEDICMP_INSTALL_MODE` را روی `source` یا `binary` قرار دهید؛ پیش‌فرض `auto` است. اجرای تست هنگام نصب از سورس با `NAMEDICMP_RUN_TESTS=1` ممکن است. `NAMEDICMP_REPO` و `NAMEDICMP_REF` تنظیمات اختیاری توسعه‌دهنده هستند؛ ref سفارشی در حالت خودکار از سورس ساخته می‌شود.

تگ‌های سرور (`v*`) پس از تست و ساخت هر دو معماری لینوکس، یک ریلیز همراه checksum منتشر می‌کنند؛ نسخه پایدار با Latest مشخص می‌شود. تگ‌های کلاینت (`namedp-v*`) فایل ویندوز را در ریلیز جداگانه می‌سازند و منتشر می‌کنند.
