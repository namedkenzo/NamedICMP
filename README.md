# namedICMP

پنل دوزبانهٔ مدیریت کاربران و هستهٔ مستقل TCP/UDP over ICMP، نوشته‌شده با Go.

**نسخهٔ 0.2.1-alpha — تم named با حالت تیره/روشن و انیمیشن‌های سبک؛ شامل اصلاح UDP و رمزنگاری اختیاری نسخهٔ 0.2.0.** از کد، باینری، اینستالر یا رابط PingTunnel و 3x-ui در این پروژه استفاده نشده است. قرارداد پیام‌های روی شبکه برای سازگاری حفظ شده، اما پیاده‌سازی از نو نوشته شده است. وابستگی‌های عمومی Go شامل `klauspost/compress` برای Zstandard و `golang.org/x/crypto` برای ChaCha20-Poly1305 هستند. تست‌های محلی موفق‌اند؛ سرعت WAN و سازگاری همهٔ کلاینت‌ها هنوز تأیید نشده‌اند.

## تم named

ظاهر اختصاصی با رنگ ذغالی و طلایی شامپاینی، لوگوی named، حلقه‌های متحرک سیگنال در صفحهٔ ورود، کارت‌ها و نمودار SVG، آیکن‌های یکپارچه، حالت روشن عاجی، فونت فارسی وزیرمتن و فونت انگلیسی Manrope. فونت‌ها داخل باینری هستند و پنل برای ظاهر به CDN یا اینترنت نیاز ندارد. حرکت‌ها با `prefers-reduced-motion` خاموش و در تب پنهان متوقف می‌شوند. چیدمان موبایل و RTL پشتیبانی می‌شود.

برای نصب قبلی، ZIP جدید را باز کنید و از پوشهٔ جدید گزینهٔ ۲، Update را بزنید؛ تنظیمات و کاربران حفظ می‌شوند.

## امکانات

- **Home:** درصد CPU، تعداد هستهٔ منطقی، حافظهٔ کل و مصرف‌شده، دیسک، شبکه، uptime، مشخصات سیستم و وضعیت هسته.
- **Users:** نام، مدت اعتبار یا تاریخ انقضا، حجم بر حسب GiB، کلید عددی اختصاصی، مصرف آپلود و دانلود، تعداد اتصال، فعال/غیرفعال، ویرایش، حذف و نمایش اطلاعات اتصال.
- **رمزنگاری اختیاری هر کاربر:** بدون رمزنگاری، AES-128-GCM، AES-256-GCM یا ChaCha20-Poly1305. پیش‌فرض کاربران جدید و قبلی **بدون رمزنگاری** است.
- کپی لینک `pingtunnel://...` و دستور CLI در قسمت اتصال؛ برای حالت‌های رمزنگاری، کلید جداگانهٔ Base64 به‌صورت خودکار تولید و نمایش داده می‌شود.
- TCP و UDP نشست‌های مستقل دارند؛ یک UDP association می‌تواند هم‌زمان چند مقصد داشته باشد. سقف datagram از ۲۰۰۰ به ۸۱۹۲ بایت افزایش یافته است.
- **Outbounds:** مستقیم، SOCKS5 با احراز هویت و UDP ASSOCIATE، و HTTP CONNECT با احراز هویت؛ قابل انتخاب برای هر کاربر.
- زبان فارسی با RTL و انگلیسی؛ حالت تیره و روشن، شامل صفحهٔ ورود؛ طراحی واکنش‌گرا و منوی همبرگری.
- قطع کاربر منقضی، حذف‌شده، غیرفعال یا دارای حجم تمام‌شده؛ سایر کاربران ادامه می‌دهند.
- تغییر کاربران، تغییر اطلاعات ورود و تمدید گواهی، هسته را restart نمی‌کنند. تغییر outbound برای اتصال‌های **جدید** اعمال می‌شود.
- مدیریت با systemd و منوی ترمینال؛ HTTP عمومی، HTTP روی localhost با SSH tunnel، یا HTTPS با Certbot.
- سهمیهٔ پایدار، ذخیرهٔ اتمیک، قفل انحصاری فایل، محدودیت اتصال و صف؛ رمز پنل با PBKDF2 و cookie با HttpOnly، SameSite و CSRF.

## نصب از سورس

نیازمندی: **Debian/Ubuntu با systemd، IPv4 عمومی، مجوز root و دسترسی اینترنت برای دانلود Go و وابستگی‌ها**. اینستالر amd64 و arm64 را پشتیبانی می‌کند و در صورت نیاز Go 1.27.2 را با SHA-256 ثابت نصب موقت می‌کند. اجرا روی VPS واقعی و Certbot در محیط ساخت این بسته ممکن نبود.

فایل ZIP را باز کنید، وارد پوشه شوید و اجرا کنید:

```bash
sudo bash install.sh
```

منو:

```text
SETUP
 1   Install
 2   Update · preserve users and settings
SERVICE
 3   Start
 4   Stop
 5   Restart
 6   Status and TCP/UDP diagnostics
 7   Recent logs
WEB PANEL
 8   SSL certificate · Certbot
 9   Change panel port
10   Change username and password
MAINTENANCE
11   Uninstall
 0   Exit
```

نصب پورت پنل، IP/دامنهٔ عمومی سرور، انتخاب SSL، نام کاربری و رمز پنل را می‌پرسد. برای HTTP سؤال می‌کند آیا فقط از localhost و SSH tunnel استفاده شود. با پاسخ «نه»، پنل به `0.0.0.0:PORT` bind می‌شود و با `http://PUBLIC_IP:PORT` در دسترس است.

برای SSL، این نسخه **دامنه** و ایمیل می‌خواهد. دامنه باید به سرور اشاره کند و TCP پورت ۸۰ برای challenge و تمدید آزاد و قابل‌دسترسی باشد. بعد از صدور، پنل به HTTPS عمومی تبدیل می‌شود؛ نیاز به ویرایش دستی تنظیمات گواهی نیست. تایمر تمدید، فایل‌های گواهی را به دسترسی سرویس می‌رساند و با SIGHUP دوباره بارگذاری می‌کند. اولین فعال‌سازی HTTPS یا تغییر پورت، سرویس را restart می‌کند؛ تمدیدهای بعدی چنین کاری نمی‌کنند.

اینستالر برای جلوگیری از بازتابِ تکراریِ بسته‌های تونل، پاسخ echo معمولی کرنل را با `net.ipv4.icmp_echo_ignore_all=1` غیرفعال می‌کند. مقدار قبلی ذخیره و در حذف بازیابی می‌شود. ICMP سرور و پورت TCP انتخاب‌شده را در firewall سرور و پنل ارائه‌دهنده باز کنید. اینستالر firewall را به‌صورت کلی تغییر نمی‌دهد و سرویس‌های ICMP قبلی را متوقف نمی‌کند؛ روی یک IPv4 دو سرور تونل مشابه را هم‌زمان اجرا نکنید.

داده‌ها در `/var/lib/namedicmp/state.json` و تنظیمات در `/etc/namedicmp/config.json` هستند. برای بازکردن دوبارهٔ منو:

```bash
sudo namedicmp
```

حذف، داده‌ها را به‌صورت پیش‌فرض نگه می‌دارد؛ نصب دوباره می‌تواند از همان داده‌ها استفاده کند. پاک‌کردن دائمی سؤال جداگانه دارد. فایل state حاوی کلیدهای اتصال و رمزهای outbound است؛ آن را در GitHub آپلود نکنید.

## به‌روزرسانی نصب قبلی

ZIP جدید را باز کنید و **از پوشهٔ همین نسخه** `sudo bash install.sh` را اجرا کنید، سپس گزینهٔ **۲، Update** را انتخاب کنید. منوی قبلیِ نصب‌شده ممکن است این گزینه را نداشته باشد. نیازی به Uninstall یا ساخت دوبارهٔ کاربران نیست.

ابتدا سورس تست و باینری جدید ساخته می‌شود و در این مرحله تونل‌ها ادامه دارند. قبل از جایگزینی، از باینری، تنظیمات و state نسخهٔ پشتیبان در `/var/lib/namedicmp/backups/` گرفته می‌شود. نام کاربری و رمز پنل، IP/پورت، TLS، کلید اتصال، سهمیه و مصرف کاربران حفظ می‌شوند. برای اعمال نسخه، سرویس یک بار متوقف و راه‌اندازی می‌شود؛ اتصال‌های فعال باید reconnect شوند. خطای بررسی سلامت، باینری قبلی را برمی‌گرداند. سرویسی که از قبل متوقف بوده، متوقف باقی می‌ماند.

برای نصب‌های GitHub، مسیر مخزن ذخیره می‌شود تا اجرای بعدی مدیر بتواند همان مخزن را دریافت کند. به‌روزرسانی همچنان نیاز به اینترنت و Go دارد؛ محیط ساخت، اجرای واقعی systemd روی VPS را تأیید نکرده است.

## آماده‌سازی GitHub

تمام محتوای این پوشه، شامل فایل‌های `.github` و `.gitignore`، سورس مخزن است. نام مخزن می‌تواند `namedICMP` باشد. هیچ credential واقعی، فایل state یا گواهی در بسته نیست.

پوشهٔ `dist` در بستهٔ دانلودی دارای خروجی Linux برای amd64 و arm64 و فایل SHA256SUMS است. این پوشه در `.gitignore` قرار دارد؛ هنگام انتشار با Git، آن را به‌عنوان سورس commit نکنید. اینستالر همچنان سورس را می‌سازد و تست می‌کند.

در بالای `install.sh` مقدار پیش‌فرض `YOUR_USERNAME/namedICMP` را با مسیر مخزن خود عوض کنید، یا متغیر `NAMEDICMP_REPO` بدهید. بعد از آپلود روی شاخهٔ `main`:

```bash
NAMEDICMP_REPO="YOUR_USERNAME/namedICMP" \
bash <(curl -fsSL https://raw.githubusercontent.com/YOUR_USERNAME/namedICMP/main/install.sh)
```

اگر مقدار پیش‌فرض داخل اسکریپت را اصلاح کرده باشید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YOUR_USERNAME/namedICMP/main/install.sh)
```

این فرمان باید به مخزن **خود شما** اشاره کند؛ لینک‌های بالا تا زمان آپلود واقعی فعال نیستند. برای نصب نسخهٔ ثابت، پس از ساخت tag، `NAMEDICMP_REF=v0.2.1-alpha` و URL همان tag را استفاده کنید. سورس از GitHub با HTTPS دریافت می‌شود؛ آرشیو سورس امضای انتشار جداگانه ندارد. workflowهای CI و ساخت خروجی Linux آماده‌اند.

## اتصال کلاینت

در پنل یک کاربر بسازید، سپس «کانفیگ» را بزنید. IP سرور و **کلید عددی همان کاربر** را وارد کلاینت سازگار با PingTunnel کنید. رمز وب پنل با کلید اتصال متفاوت است.

دکمهٔ «کپی لینک اتصال» دقیقاً این قالب را می‌دهد:

```text
pingtunnel://SERVER_IP_OR_DOMAIN?lport=1080&mode=vpn&key=USER_NUMERIC_KEY
```

پذیرفتن این URI و گزینهٔ `mode=vpn` به اپ کلاینت بستگی دارد؛ لینک به‌تنهایی قابلیت VPN/TUN یا UDP را به کلاینت اضافه نمی‌کند.

نمونه با کلاینت رسمی PingTunnel روی Linux، با دسترسی raw ICMP:

```bash
sudo pingtunnel -type client -l 127.0.0.1:1080 \
  -s YOUR_SERVER_IP -sock5 1 -key YOUR_USER_KEY -tcp_gz 0
```

پروکسی محلی روی `127.0.0.1:1080` ساخته می‌شود؛ برای VPN تمام دستگاه، اپ موبایل باید حالت VPN/TUN خود را ارائه دهد. namedICMP تونل TCP/UDP و سرور پروکسی است، سرور لایهٔ ۳ با interface TUN نیست.

**برای UDP:** کلاینت باید UDP را مستقیماً به‌صورت datagram روی ICMP بفرستد. در حالت SOCKS، کلاینت PingTunnel و برنامهٔ مصرف‌کننده باید UDP ASSOCIATE را پشتیبانی کنند. کلاینت‌های قدیمی که فقط TCP دارند، HTTP CONNECT و قرار دادن Shadowsocks TCP داخل یک تونل TCP، UDP را خودکار حمل نمی‌کنند. خروجی کاربر باید Direct یا SOCKS5 دارای UDP باشد؛ HTTP CONNECT فقط TCP است و به مسیر مستقیم fallback نمی‌کند. گزینهٔ ۶ منو شمارنده‌های `udp_packets_in/out` و `tcp_packets_in/out` را جدا نشان می‌دهد.

**برای رمزنگاری:** در افزودن/ویرایش کاربر یکی از روش‌ها را انتخاب کنید. عدد `key` همچنان کلید دسترسی است؛ پنل علاوه بر آن، کلید رمزنگاری تصادفی Base64 می‌سازد. برای CLI سازگار، به دستور بالا اضافه کنید:

```bash
-encrypt aes128 -encrypt-key 'BASE64_KEY_FROM_PANEL'
# یا: -encrypt aes256 / -encrypt chacha20 با کلید همان کاربر
```

روش و کلید باید در دو طرف یکسان باشند. دستور کامل قابل‌کپی پنل این گزینه‌ها را اضافه می‌کند. **URI درخواستی فقط سرور و کلید عددی را دارد**؛ برای کاربران رمزنگاری‌شده، روش و کلید رمزنگاری را جداگانه در اپ وارد کنید. فیلد اختصاصی و تأییدنشده به URI اضافه نشده است. تغییر روش فقط نشست‌های همان کاربر را قطع می‌کند؛ ویرایش نام، سهمیه یا فعال/غیرفعال کردن، روش رمزنگاری را خودکار تغییر نمی‌دهد. کاربران قبلی پس از Update روی «بدون رمزنگاری» باقی می‌مانند.

سازگاری هدف: پیام protobuf PingTunnel، ICMPv4 echo، کلید مثبت ۳۱ بیتی، UDP forwarding و TCP frameهای CONN/CONNRSP، ACK/REQ، heartbeat و CLOSE. رمزنگاری اختیاری از قالب `nonce | ciphertext | tag` و کلید خام Base64 مطابق قرارداد کلاینت مرجع استفاده می‌کند. ورودی TCP فشردهٔ Zstandard پشتیبانی می‌شود؛ خروجی بدون فشرده‌سازی است. IPv6 به‌عنوان حامل ICMP و تضمین کارکرد همهٔ اپ‌های Android/iOS ارائه نمی‌شود. HTTPS پنل و رمزنگاری ICMP دو تنظیم مستقل‌اند.

برای تست واقعی، راهنمای [قبول نسخه و سازگاری](docs/ACCEPTANCE.fa.md) را بخوانید. نصب روی سرور اصلی پیش از این تست توصیه نمی‌شود؛ عدم کپی کد، به‌تنهایی تضمین سازگاری یا سرعت نیست.

## ساخت و بررسی

Go 1.26 یا بالاتر (ساخت این بسته با Go 1.27.2):

```bash
go mod download
go test -race ./...
go vet ./...
bash scripts/test_installer.sh
bash scripts/test_update.sh
CGO_ENABLED=0 go build -buildvcs=false -trimpath -ldflags='-s -w' \
  -o bin/namedicmp ./cmd/namedicmp
```

پیش‌نمایش پنل بدون raw ICMP، با دادهٔ آزمایشی جداگانه:

```bash
mkdir -p /tmp/namedicmp-demo
printf '%s\n' '{"username":"admin","password":"REPLACE_WITH_12_PLUS_CHAR_PASSWORD"}' | \
  ./bin/namedicmp init --config /tmp/namedicmp-demo/config.json \
  --state /tmp/namedicmp-demo/state.json --listen 127.0.0.1:8443 \
  --public-host YOUR_SERVER_IP
./bin/namedicmp serve --config /tmp/namedicmp-demo/config.json \
  --panel-only --admin-socket=''
```

`--panel-only` صرفاً برای توسعه است و کانفیگ‌های ICMP در آن اتصال ندارند. سرویس نصب‌شده این گزینه را استفاده نمی‌کند.

تست اختیاری رابط با Node 20+ (Node برای اجرای پنل لازم نیست):

```bash
npm ci --ignore-scripts
npm run test:ui
```

این تست DOM با API واقعی، ورود، کاربران و خروجی، پیش‌فرض خاموش رمزنگاری، انتخاب AES، URI و کپی، زبان، تم و خروج از پنل را بررسی می‌کند؛ جای بررسی تصویری در مرورگر را نمی‌گیرد.

## معماری و محدودیت سرعت

هسته در `internal/core`، قالب شبکه در `internal/wire`، ذخیره‌سازی در `internal/store`، outboundها در `internal/outbound` و پنل در `internal/panel` هستند. UI در باینری embed می‌شود و به Node یا CDN نیاز ندارد. مسیر بسته‌ها subprocess اجرا نمی‌کند؛ نمایش آمار سیستم هر ۵ ثانیه نمونه‌برداری می‌شود. نشست‌ها goroutine جدا و صف محدود دارند و برای فعالیت یا موعد retransmit منتظر می‌مانند.

حساب هر کاربر با کلید مستقل مشخص می‌شود. شناسهٔ نشست از **کاربر + IP مبدأ + شناسهٔ اتصال + TCP/UDP** و در UDP علاوه بر آن **مقصد** تشکیل می‌شود؛ شناسهٔ یکسان، کاربران یا دو پروتکل یا مقصدهای UDP را مخلوط نمی‌کند. در TCP هر فریم فقط یک بار به مسیر حسابداری داده می‌شود. UDP تضمین exactly-once ندارد و هر datagram دریافتی مصرف محسوب می‌شود. خطا یا پایان عمر یک جریان UDP، KICK مبهمی که TCP هم‌نام را قطع کند نمی‌فرستد.

زمان‌بندی retransmit اکنون heap دارد و در هر دریافت همهٔ فریم‌های معلق را اسکن نمی‌کند. خواندن TCP تا ۳۲ فریم با یک بافر انجام می‌شود؛ دادهٔ آماده هنگام کوچک‌شدن پنجره حفظ می‌شود. یک موج timeout پنجره را یک بار کوچک می‌کند. state بدون تغییر دوباره fsync نمی‌شود؛ تضمین سهمیهٔ پایدار حفظ شده است. جزئیات اندازه‌گیری و حدود آن در [گزارش تست](docs/TEST_REPORT.md) آمده؛ این بهبودها اثبات افزایش سرعت WAN نیستند.

رزرو پایدار در بلوک‌های ۲۵۶ KiB انجام می‌شود، نه fsync برای هر بسته. مصرف زنده دقیق است؛ پس از shutdown عادی دقیق باقی می‌ماند. پس از قطع برق/kill -9، رزرو استفاده‌نشده هم محافظه‌کارانه مصرف می‌شود: معمولاً حداکثر **۲۵۶ KiB اضافه برای هر کاربر**. مقدار آن جداگانه در `recovery` دیده می‌شود. quota هیچ‌وقت به دلیل کرش به عقب برنمی‌گردد. دادهٔ پذیرفته‌شده پیش از ارسال به مقصد حساب می‌شود؛ شکست بعدی مقصد باعث refund نمی‌شود. خطای ذخیره‌سازی، ترافیک را متوقف می‌کند تا مصرف بدون ثبت ادامه پیدا نکند.

پنجرهٔ ID پیش‌فرض ۲۰۰۰۰ حفظ شده است، اما حداکثر ۱۰۲۴ فریم در پرواز و ۱۰۲۴ فریم خارج از ترتیب در حافظه نگهداری می‌شود. این محدودیت و الگوریتم کنترل ارسال با PingTunnel یکسان نیستند و ممکن است روی مسیرهای پُرتأخیر یا دارای loss روی throughput اثر بگذارند. پیش‌فرض ۲۵۶ نشست کل، ۳۲ نشست TCP و ۱۲۸ جریان UDP برای هر کاربر و سقف حافظهٔ systemd برابر ۷۶۸ MiB است. جریان UDP به ازای هر مقصد شمرده می‌شود. UDP بالاتر از ۸۱۹۲ بایت رد می‌شود؛ بسته‌های بزرگ ممکن است به fragmentation IPv4 نیاز داشته باشند که به شبکه بستگی دارد. این اعداد ظرفیت تضمین‌شده نیستند. جزئیات در [طراحی و پروتکل](docs/ARCHITECTURE.md).
